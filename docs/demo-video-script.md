# Demo 视频脚本（3 分钟以内）

要求回顾（来自挑战说明）：①目标用户及核心痛点；②设计思路与关键取舍；③核心功能及亮点演示；④其他想表达的。前 30 秒决定生死，wow moment 放最前面。一镜到底即可。

核心叙事：**自指演示**——挑战结束后第二周有 1v1 现场答辩，我把本项目自己的 GitHub 仓库输入给我自己做的产品，让它帮我准备这场答辩。产品出的题够不够狠，评委看完视频后在答辩现场可以亲自验证。

录制准备：

- 提前用本项目仓库（`MistySun19/PKU-AI-Interviewer`）完整跑通一次生成，把报告页开在第二个标签备用，挑好 1-2 道最狠、证据最具体的题。
- 浏览器只留产品页标签，地址栏输入公网 URL（顺便证明可访问）。
- 本仓库是 agent 类 AI 项目，会命中 method / agent 方向的理解 skill，确认报告里有体现。

## 0:00 - 0:30　Wow Moment（自指开场）

画面：产品输入页，粘贴本项目自己的仓库链接；随即切到已生成报告里的一道拷打题。

台词参考：

> 两周之后，我要为眼前这个项目接受一场 1v1 现场答辩。而帮我准备这场答辩的，就是这个项目自己。
> 我把它的 GitHub 仓库输进去，它读完了自己的代码，然后问了我这样一道题——（指着屏幕念出那道题，例如：）"你的编排器里 digest worker 并发上限是 3，这个数字是怎么定的？改成 10 会发生什么？"
> 它指着的是真实的文件和真实的设计决策。这就是我做的产品：一个先读懂你仓库、再拷打你的 AI 面试官。

## 0:30 - 1:00　目标用户与痛点（访谈证据）

台词参考：

> 我访谈了 5 位准备实习和保研的同学，加上我自己的面试经历，发现一个共同模式：研究岗、算法岗、保研认真导师，主线都是项目深挖——面试官会从你代码的一个细节，一路追问到原理。
> 同学的原话是：最怕的不是没做过，而是"做过但忘了细节"。比如被问"Diffusion 的 timestep 是怎么注入的"，当场卡住。
> 题库和 ChatGPT 帮不了这个忙——它们没读过你的仓库。

## 1:00 - 1:30　设计思路与取舍

画面：架构图（docs/ARCHITECTURE.md）。

台词参考：

> 所以我的设计判断是：先把"读懂仓库"做扎实，其他都后置。我刻意砍掉了 JD 匹配、题库堆量和语音视频——因为仓库理解不准的时候，这些只会把泛问题包装得更像样。
> 系统是一个 Repo Deep Research Agent：先做 repo map 和文件骨架化，再按项目类型分维度并行深读，最后合成一份面试计划。

## 1:30 - 2:30　核心功能演示（继续用自己的仓库）

画面：现场粘贴仓库链接展示流式过程约 20-30 秒，然后切到完整报告标签页走读。

台词参考：

> 你可以实时看到它在读哪些文件、形成了什么判断——现在它正在读它自己。
> （切到完整报告）最终输出一份项目考核面试计划：项目主张摘要、复现路线、核心方法代码地图——然后是重点：分层面试问题。
> 每道题都有：仓库证据来源、面试官为什么会问、期望回答要点、红旗回答、追问链。比如它问我"为什么用 GitHub REST API 而不是 git clone"——这正是我开发时真实做过的取舍，答辩时大概率会被问到。
> 也就是说，你不仅提前知道会被问什么，还知道答到什么程度才算过关。

## 2:30 - 3:00　差异化与收尾

台词参考：

> 和直接用 ChatGPT 的区别就一句话：它拿到的是你仓库的一手证据，每道题都拷在真实代码上，拷不到证据的题进不了主追问链。
> 下一步我会接入真实面经高频题库做校准，并支持选一道题进入实时连续追问。
> 两周后的答辩，我会带着它给我生成的这份面试计划去。如果我答得好，功劳有它一半；如果它问得比评委还狠，那就是这个产品最好的证明。谢谢观看。
